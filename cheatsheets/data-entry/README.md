# Кабинет автора · data-entry/

Офлайн-инструменты для наполнения контента «Шпаргалкаҳо» без ручного
редактирования JSON. Два самодостаточных HTML-файла — ни сборки, ни
сервера, ни секретов. Файлы ссылаются друг на друга через навигацию в шапке.

- **`index.html`** — редактор карточек (`content/cards/*.json`).
- **`subjects-topics.html`** — редактор предметов и тем
  (`content/subjects.json` и `content/topics.json`).

Визуально оба файла оформлены в стиле лендинга приложения
(`elxak.github.io/cheatsheets/index.html`): те же токены — `--brand:#0D4CCF`,
`--ink:#0E1A3D`, `--paper:#F2F6FF`, `--accent:#FFD23F`, шрифты Unbounded +
Manrope, сквозная шапка со стеклянным блюром и тот же футер «Разработан
~/elxak.dev».

## Как открыть

**Вариант A — просто открыть файл.** Дважды кликните `index.html` или
`subjects-topics.html`. Работает полностью, кроме автозагрузки
`subjects.json`/`topics.json` (браузеры блокируют `fetch()` локальных файлов
через `file://`) — в этом случае загрузите оба файла вручную кнопками в
левой панели.

**Вариант B — через локальный сервер** (тогда автозагрузка сработает, если
`data-entry/` лежит рядом с `content/` в дереве проекта):

```bash
cd cheatsheets_app
python3 -m http.server 8080
# откройте http://localhost:8080/data-entry/
```

**Вариант C — GitHub Pages.** Можно опубликовать `data-entry/index.html` как
статическую страницу (например, скопировав в `docs/` или в отдельный
репозиторий) — инструмент от этого не меняется, он ничего не отправляет на
сервер.

## Что делает редактор карточек (index.html)

- Выбор предмета/темы из загруженных `subjects.json`/`topics.json`, либо
  ручной ввод `topicId`.
- Форма карточки: id, трёхъязычный заголовок (ru/en/tj), теги, флаг
  `fixedByUser`, блоки всех 6 типов (текст/формула/таблица/список/
  изображение/пример) с вложенным редактором решения внутри примера.
- Каждое переводимое поле — переключатель «одинаково / разный текст по
  языкам», как и требует схема проекта (`l10n`: строка или `{ru,en,tj}`).
- Живой предпросмотр в виде карточки-каталога (с рендером LaTeX через KaTeX).
- Панель JSON с подсветкой синтаксиса, кнопками «Копировать» и «Скачать файл
  темы» (`<topicId>.json` — кладите прямо в `content/cards/`).
- Проверки в реальном времени: пустые обязательные поля, несовпадение числа
  ячеек в строках таблицы, опечатки «слипшейся» латиницы с кириллицей/
  таджикскими буквами (та же эвристика, что и в `tool/validate_content.py`),
  незакрытые `$…$`, неполный перевод по языкам.
- Черновик автосохраняется в `localStorage` браузера — не потеряется при
  случайном закрытии вкладки. Кнопки «Импортировать файл темы» позволяют
  открыть существующую карточку из `content/cards/*.json` на редактирование
  (в том числе чтобы проставить `fixedByUser` после проверки отчёта из
  Telegram-бота).
- Ctrl+Z отменяет последнее удаление блока (однократный буфер).

## Что делает редактор предметов и тем (subjects-topics.html)

- Загрузка существующих `subjects.json`/`topics.json` (или начало с нуля).
- Список предметов слева: цветной значок-иконка (ровно те же имена иконок,
  что понимает `_subjectIcon()` в `lib/screens.dart` — выпадающий список, а
  не свободный текст, с живым превью реальной Material-иконки), название,
  количество тем, реордер стрелками ↑/↓, удаление.
- Форма предмета: id, трёхъязычное название, иконка, цвет (палитра + hex-поле
  синхронизированы).
- Темы предмета — раскрывающиеся строки: id, трёхъязычное название, класс
  (1–12 или не указан), сложность (лёгкая/средняя/сложная или не указана),
  реордер и удаление. `order` при экспорте выставляется автоматически по
  позиции в списке — вручную вводить не нужно.
- Проверки: формат id, уникальность id (отдельно для предметов и для тем),
  ссылочная целостность (`topicId` темы должен существовать среди
  предметов), диапазон класса 1–12, корректность hex-цвета, опечатки той же
  эвристикой, что и в карточках, предупреждение о предмете без тем.
- Панель JSON с переключателем **subjects.json / topics.json** — экспорт
  каждого файла отдельной кнопкой «Скачать файл» (не смешиваются в один).
- Черновик — в `localStorage`, отдельно от черновиков карточек.

## Чего инструменты **не** делают (осознанно)

- **Не отправляют данные никуда сами.** Готовый JSON нужно скачать и вручную
  прислать администратору (Telegram/почта/как удобно) или сразу положить в
  `content/` при пуш-доступе к репозиторию.
- **Не хранят токен Telegram-бота.** Встраивать `TELEGRAM_BOT_TOKEN` в
  статическую HTML-страницу небезопасно — любой посетитель может прочитать
  исходный код страницы и получить токен. Если понадобится приём карточек
  прямо из формы, правильный путь — небольшая serverless-функция
  (Cloudflare Worker/Vercel Function), которая держит токен на своей стороне
  и проксирует запрос в Telegram; сами эти HTML-файлы для такой интеграции
  менять не придётся, только добавить один `fetch()` к адресу функции.
- **Не валидируют по полной JSON Schema.** Проверки в браузере — эвристики
  для быстрой обратной связи автору. Финальная проверка всё равно происходит
  через `python tool/build_content.py` (JSON Schema + проверка версий +
  ссылочная целостность) перед коммитом.

## После экспорта

1. Скачанный `<topicId>.json` кладите в `content/cards/`; `subjects.json`/
   `topics.json` — прямо в `content/` (заменяя старые файлы целиком, это не
   инкрементальные патчи).
2. `python3 tool/build_content.py` — пересобирает `assets/content/content.json`
   и валидирует по схеме.
3. При необходимости бампните `content/meta.json` (`version`) и
   `kContentVersion` в `lib/sqlite_repository.dart` синхронно — см.
   AUTHORING.md, раздел «Когда менять версию».
